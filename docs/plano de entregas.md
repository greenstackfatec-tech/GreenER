# Definition of Done

Uma história de usuário ou item do backlog só será considerado concluído quando atender a todos os critérios aplicáveis abaixo.

## Checklist

| Critério | Descrição | Concluído |
|---|---|---|
| Implementação | A funcionalidade foi implementada conforme a história e seus critérios de aceitação. | [ ] |
| Frontend | A interface foi implementada em React com TypeScript, quando aplicável. | [ ] |
| Backend | A lógica foi implementada em Node.js com TypeScript, utilizando a organização definida pelo projeto. | [ ] |
| Banco de dados | As alterações necessárias foram implementadas em PostgreSQL utilizando DDL e DML, sem ORM. | [ ] |
| Integração | Frontend, backend e APIs auxiliares foram integrados corretamente. | [ ] |
| Tratamento de erros | Falhas, indisponibilidade e respostas inválidas foram tratadas sem interromper a aplicação. | [ ] |
| Critérios de aceitação | Todos os critérios de aceitação da história foram verificados e atendidos. | [ ] |
| Testes | Foram realizados testes compatíveis com a funcionalidade, incluindo cenários de sucesso e falha. | [ ] |
| Responsividade | A interface foi validada em diferentes tamanhos de tela, quando aplicável. | [ ] |
| Segurança | A funcionalidade não introduz vulnerabilidades conhecidas e respeita a autenticação e autorização do sistema. | [ ] |
| Documentação | A documentação técnica, os endpoints ou as instruções afetadas foram atualizados. | [ ] |
| Docker | A aplicação continua executando corretamente por meio dos containers Docker. | [ ] |
| Revisão | O código foi revisado por pelo menos um integrante da equipe. | [ ] |
| Demonstração | A funcionalidade está pronta para ser demonstrada na sprint review. | [ ] |

## Observações

- Itens não aplicáveis devem ser justificados na descrição da tarefa ou no registro da sprint.
- Uma tarefa não deve ser marcada como concluída apenas porque o código foi escrito.
- O item deve estar integrado à versão do projeto utilizada pela equipe para a demonstração.
